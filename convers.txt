     Discount Code Feature – Implementation Plan

     Context

     The cart (Flask on Lambda + React/Vite, DynamoDB) computes
     subtotal/tax/total in the backend only and has no concept of discounts. Add
     the ability to apply a discount code to the cart, reflect it in totals,
     and persist it on the order. Final deliverable of this plan: copy to
     docs/discount-code-plan.md (plan mode blocks writing there now; do it on
     approval).

     Design decisions (defaults, adjust if needed)

     - Code definitions: stored in a new DiscountsTable (hash key code; attrs
       type = percent|fixed, value, active, optional expiresAt), seeded on first
       read like ProductService._seed_products (e.g. SAVE10 10%, FIVEOFF $5).
     - Applied code: stored per session in the existing Cart table as a sentinel
       item (productId = "__discount__")? That pollutes get_items. Recommended
       instead: new attribute-free approach — put it in the Discounts table?
       Simplest clean choice: a separate appliedCode record in the Cart table 
       with sentinel key, filtered out in CartModel.get_items. Single code per
       cart.
     - Math: discount applies to subtotal; tax computed on discounted subtotal;
       discount capped at subtotal. Centralize the 8% rate and rounding in one
       helper (currently duplicated in cart_service.get_cart and
       order_service.create_order).
     - Order creation re-validates the code server-side; never trust client
       totals.

     Files to change

     Backend

     - template.yaml – add DiscountsTable resource, DISCOUNTS_TABLE env var,
       DynamoDBCrudPolicy.
     - backend/models/discount.py (new) – table wrapper, copy
       _serialize/_deserialize pattern from models/cart.py.
     - backend/models/cart.py – get/set/clear applied code; make get_items skip
       the sentinel; add explicit Key import (currently relies on order.py).
     - backend/services/discount_service.py (new) – validate(code),
       calculate(subtotal, discount), seeding.
     - backend/services/cart_service.py – get_cart returns discountCode,
       discount, tax on discounted subtotal; add apply_discount/remove_discount;
       use shared totals helper.
     - backend/services/order_service.py – accept discount, use shared totals
       helper, store discountCode + discount.
     - backend/models/order.py – add discount to the Decimal key lists in
       _serialize/_deserialize.
     - backend/routes/cart.py – POST /api/cart/discount (body {code}; 400
       missing/invalid/expired) and DELETE /api/cart/discount, per
       docs/api-standards.md (validate input, {"error": ...}, try/except +
       logging, no boto3 in routes).
     - backend/routes/orders.py – pass the cart's discount to
       order_service.create_order; clear the applied code after the order
       (alongside clear_cart).
     - backend/services/cart_service.py clear_cart should also remove the
       applied code.

     Frontend

     - frontend/src/services/api.js – applyDiscount(code), removeDiscount().
     - frontend/src/context/CartContext.jsx – applyDiscount/removeDiscount (call
       API, then fetchCart()); add discount, discountCode to initial state.
     - frontend/src/pages/CartPage.jsx – code input + Apply button, applied-code
       chip with remove, "Discount" row in .cart-summary; show errors inline
       (not alert).
     - frontend/src/pages/OrdersPage.jsx – optionally show discount on past
       orders.
     - frontend/src/styles.css – styles for the input/chip/discount row.

     Tests & docs

     - backend/requirements.txt + backend/tests/ (new; none exist despite
       README) – pytest + moto; test_discount_service.py, test_cart_service.py
       (totals with percent/fixed/cap/invalid/expired), order creation with
       discount.
     - README.md – add endpoints to table and files to structure tree.
     - docs/discount-code-plan.md – this plan.

     Verification

     1. pytest backend/tests passes (percent, fixed, cap at subtotal, invalid,
        expired, remove, order stores discount).
     2. Run backend locally (flask run, port 5000) + npm run dev in frontend/:
        add items, apply SAVE10 → discount row and lower tax/total; remove code
        → totals revert; bad code → inline error.
     3. Check out with a code → order shows discount; cart clears and code is
        cleared.
     4. sam validate / sam build for the template change; deploy via deploy.sh
        and smoke-test the API.

     Open questions

     - Tax before/after discount (assumed after).
     - One code per cart (assumed) and whether codes need usage limits.

  How it works

  - Codes: a new DynamoDB table holds the codes. It seeds SAVE10 (10% off),
    FIVEOFF ($5 off) and EXPIRED the first time a code is validated.
  - Applying a code: POST /api/cart/discount takes {"code": "..."} and DELETE 
    /api/cart/discount removes it. A bad, empty or expired code returns 400 with
    an error message.
  - Storage: a cart holds one code, saved as a hidden row in the cart table.
  - Totals: tax is charged on the discounted subtotal, and the discount can't
    exceed the subtotal.
  - Re-checking: the code is re-checked every time the cart loads, so an expired
    code stops applying on its own. Checkout saves discount and discountCode on
    the order, and a successful order also clears the applied code.
  - Shared totals code: both the cart and order code now use one helper,
    services/pricing.py. This replaced two places that each had the 8% rate
    hardcoded.
  - Frontend:
    - A new DiscountCodeForm component sits in the cart summary and shows errors
      inline.
    - There's a discount line in the cart summary.
    - Past orders show the discount.
    - I also added a cart refetch after checkout, so the cart doesn't keep
      showing a stale code.
    - The new component follows your React rules, with no inline styles.
